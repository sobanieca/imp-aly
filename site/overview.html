Analytics for your imp apps, on a VPS that you own.

imp-aly is one small binary. It takes the records of imp/analytics, checks each one against the build file of your app, and stores them on the local disk. Then it answers your queries. No database, no third party, and the data stays on your machine.

curl -fsSL sobanieca.github.io/imp-aly/install.sh | bash

How it works

The public port takes records from any browser. The server checks them, writes them to a synced log, and then answers. The admin port answers only calls that are signed with the key. The key never goes over the network.

What you get

One file, no database

The server is one binary with no runtime and no dependency. It keeps the records in plain text column files, one folder per app and day.

Safe from the first answer

The server syncs each batch to a write-ahead log before it answers 202. A crash a second later loses no accepted record.

Only correct records

Each page, zone and outcome must be in the lists of app-analytics.json from imp build. Run imp-aly app refresh after each deploy. Strict field rules and a rate limit per address stop junk and floods.

History as long as the disk

No age limit. When the disk gets full, the oldest days lose their records first and keep their small daily summaries.

Fast queries

Most queries read only the daily summaries. Group by page, type, zone, outcome, country or your own segments, and by day, week or month. Count records and visits.

Viewed, and also used

imp marks a page view as used at the first click, tap or key on the page. See which pages people open but do not use, with no setup in your app.

Several servers, one answer

imp-aly query -s eu,us asks each server and adds up the counts. The result is the same as from one server with all the records.

A key that stays home

Each call carries a one-time token, signed for one request and valid for 60 seconds. The key itself is never sent.

Small backups

imp-aly backup saves the daily, week or month summaries to a compressed file. Restore it on any server and query it.

Your imp app main.js

import { onAnalytics } from 'imp/analytics'
import { alySink } from 'imp/analytics/aly'

onAnalytics(alySink({
  app: 'myapp',
  servers: ['https://aly.myapp.example'],
}))

The sink is part of imp. See Getting started for each step.

/imp-aly which pages do people open but not use?

Install

curl -fsSL sobanieca.github.io/imp-aly/install.sh | bash

Use the same command on the VPS and on your machine. It supports Linux and macOS on x64 and arm64. As root with systemd, imp-aly server installs a service that runs as its own user. imp-aly help lists every command. Until version 1.0.0, any part of imp-aly can change.

It installs to /usr/local/bin, for all users. If you can't write there, run it with sudo bash instead of bash, or install to a custom location: set INSTALL_DIR to a directory on your PATH, as in curl -fsSL sobanieca.github.io/imp-aly/install.sh | INSTALL_DIR=~/.local/bin bash.
